# Portable control policy

A control Skill turns maintained behavioral memory into a bounded execution decision:

```text
intent
→ behavioral edge
→ implementation ownership
→ supported operation
→ observable oracle
→ reconciled denominator
```

Keep three knowledge classes distinct:

- Hard: subject identity, boundary preservation, observable proof, blocker completeness, and denominator reconciliation.
- Soft: preferred discovery order, stable handles, polling, and risk-based journey reduction.
- Discoverable: ambient identifiers, paths, ports, credentials, availability, and incidental runtime facts.

Feature topology and implementation topology are separate graphs. Cross-graph mappings must be explicit and falsifiable. Missing ownership is a stop condition, not permission to infer.

The compiler may derive affected edges and required journeys from declared mappings. It must not invent domain facts, execute an unavailable runtime, or promote lower evidence.
