# shadow-architect

**One question:** is the shape of this change the smallest one that satisfies
its issue, and can every part of it name the process that reads it?

The wave monitor has been asking that question for a dozen waves. Until now it
asked it out of a prompt line pointing at a directory on one machine — no pin,
no digest, hundreds of commits of divergence between the copy the prompt read
and the copy anyone else could read. That is an ambient dependency, and clause
P7 of this bundle refuses exactly it. This bundle is the same question as
admitted bytes.

Roles: **BUILD** is the only half that changes the ledger — one adjudicated
precedent at a time, behind the repository's cure-authorization refusal, landing
through the PR ceremony. **SHADOW** is reader-only: it matches, quotes, and asks
at severities S0 observe / S1 warn / S2 review, and never writes into the subject
it reads. A SHADOW pass whose subject digest moved refuses its own report.

## What it is not

It does not decide. Every finding is a question with the added bytes that raised
it quoted beside it, and the schema refuses a finding that carries no question —
because the shape of a change is judged by whoever can answer "what reads this",
and that is the person who wrote it. It runs no experiment against a subject
either: `red-team` owns the falsification verb, and the differential between the
two is deliberate.

## Why every clause carries a real judged diff

A ledger of architecture rules is an opinion registry unless something ever saw
each rule fire. So each precedent names four things and the validator ties all
four: the wave receipt that recorded the finding, the monitor record that wrote
it down, the real judged diff it was issued against — whose own bytes must name
the commit the provenance claims — and a real diff where the same clause must
stay silent. A clause whose own fixture does not raise it reds. A clause raised
by the diff that cured it reds too, because a detector that fires on the cure is
detecting the subject rather than the shape.

The extraction is bounded on purpose. Only the seven principles wave monitors
actually cited are here; nothing was imported wholesale, and no clause was
invented to round the set out.

## The campaign is blind

The planted arm carries an over-designed diff and a clean one that has an
artifact of every kind the over-designed one has. The driver takes one diff path
and opens that path only, so it cannot see the answer key that says which
clauses each arm should raise; a script in this bundle that named the key would
red the validator. The key is read after the run, by the test that compares.

## Run it

```sh
python3 skills/shadow-architect/scripts/shadow_driver.py --diff <path>           # a reader-only pass
python3 skills/shadow-architect/scripts/shadow_driver.py --diff <path> --render  # the issue-body block
python3 skills/shadow-architect/scripts/validate_shadow_architect.py --selftest
python3 -m unittest discover -s skills/shadow-architect/tests
```
