# Source proposal — arrival-engineering

Source kind: **owner-design-brief**. There is no upstream repository to freeze;
the source is an adjudication recorded on the provider (`ed3c/skill-concerns#73`)
and reproduced here as the frozen brief. The birth and upkeep ceremonies are
pinned upstream bytes, locked by blob identity in `source-lock.json`.

## The physical trigger

Five islands of one class surfaced in a single day, each found by hand:

1. An offline-provable code-intel core with zero runtime consumers: no verb, the
   execution skill silent, navigation in practice unguided text search.
2. A false documented pin: a module header claiming its tool pins were mirrored
   in a lock file whose live bytes carried no such entries.
3. Dangling cross-repo pointers: a code-intel topology naming probe interfaces
   whose carrier had been adjudicated retired upstream (`ed3c/noodles#293`).
4. Four migration probe scripts with `__main__` entrypoints and no
   re-verification surface — silent rot until some future evidence re-run.
5. The near-miss the cure exposed: a runtime verb a consumer "may remember to
   call" — a planned island. The amendment bound the capability to the checkout
   ceremony and made cross-repo receipts inadmissible without it
   (`ed3c/noodles#294`).

The class: **declared capability with no bound consumer, or a consumption claim
above its measured arrival**. Every instance was caught by ad-hoc audit. The
class needs an owner.

## What the bundle owns

One question, mechanized: for each declared capability, who consumes it, through
which bound exit, and at which measured arrival level — and does every claim
match?

It is the single owner of the **DECLARED / EXERCISED / PRODUCTION** arrival
vocabulary. Other bundles may cite those levels; none may redefine them.

## Birth and upkeep ceremonies (pinned, read-only)

Generated under `pstack/skills/create-verification-skill` and maintainable by
`pstack/skills/maintain-verification-skill`, both read from the canonical
read-only clone at the commit pinned in `policy/upstream-pins.json`. Their blob
identities are locked in `source-lock.json` so a ceremony change is visible as
drift rather than as prose.

The interview-repo step was run against this repository's own reality: the
surface is a Python control plane driven by `scripts/run_all.py`; Doctor is each
bundle's validator plus `--selftest`; Drive is the island audit over a tree;
Evidence is `receipts.json`, the admission receipt, and the campaign fixtures;
the feature map is `domain/capability-topology.json`, one row per capability.

## Boundaries adjudicated at birth

- Runtime and session liveness stay with `dynamic-workflow`.
- The code-intel method stack stays with `control-code-intel`.
- Compiled context projections and the closure laws stay with
  `context-closure-engineering`; clause A6 points at LAW-TRACE-GAP and
  LAW-NO-PROMOTION and restates neither.
- Supervised-execution conduct stays with `spatial-loop-grounded`, whose
  behavioral-campaign shape this bundle reuses.

Falsifiable merge trigger: if two consecutive maintain passes show every
topology row already owned by a `spatial-loop-grounded` or
`context-closure-engineering` clause, that is the merge signal — file it then,
not before.

## Non-claims

No new scheduler, no daemon, no runtime-liveness scope, no cross-repo writes in
either mode, no aspirational topology rows, no auto-cure. BUILD proposes; the
machine ceremony lands.
