# Source proposal — red-team

Owner design brief, adjudicated 2026-09-01, filed as ed3c/skill-concerns#94.
Frozen here by content digest before any refactoring; the bundle is derived
from this brief and from the pinned pstack ceremonies named in
`intake/red-team/source-lock.json`.

## The tension this resolves

Rule front-loading must not tax the working agent's generation. Moving the
rules into a monitor's clean context resolves it: the worker stays free, and
carrying the full pattern catalogue is the monitor's whole job.

## The capability, already homeless

The wave judge's adversarial method — rewrite-all-to-the-exit experiments,
planted-direction replay, producer re-runs in throwaway clones, pristine-main
controls, the GraphQL second-arrival probe — has produced the strongest
findings of the last five waves, yet the judge rules live only in dispatcher
prompt text and scratchpad notes. That is the same temp-dir island class this
machine adjudicated for the body editor: a capability with no pinned bytes.

## One organ, two invocation points

1. **Front-load as the job.** Read the pinned catalogue at an exact commit —
   the slop pattern classes from the cross-wave judge ledger and the
   admission-architecture atoms. The catalogue is bytes, never improvised.
2. **SHADOW, the monitor role.** At each stage boundary, match new artifacts
   (diffs, lane reports, receipts, filed issues) against the catalogue and run
   sampled falsification experiments. Findings are numbered receipts and
   questions, delivered at the boundary. No hit means "no findings", which is
   the honest and expected steady state.
3. **Run ledger.** Every run appends one record — wave, boundary, classes
   sampled, hits per class, novel-class candidates. The declining curve reads
   from that file: known-class recurrence must trend to zero as classes gate,
   and a non-declining curve after three post-admission waves is itself a
   finding about the architecture, delivered to the dispatcher.
4. **Judge unification.** The wave-close judge consumes the same skill bytes as
   its rules source. Single source; the boundary runs and the close run are the
   same method at different points.
5. **BUILD, the catalogue fold-in.** A new pattern enters only from an
   adjudicated verdict or ledger entry, behind the BUILD-authorization refusal.
   Detection is the beginning of adjudication, never a licence to legislate.
6. **Intervention boundary, drawn hard.** Never any mid-flight injection into a
   working agent or its subject; reader-only against subjects, experiments in
   throwaway clones. Real-time is legal in exactly one direction: an escalation
   signal to the dispatcher, who holds stop authority. Irreversible-class
   dangers stay owned by the architecture layer — branch protection, sandbox
   scope — not by monitor heroics.

## Physicalized handoff

The finding-to-issue mechanism is a machine shape, not dispatcher prose:
findings are validator-owned records with an experiment block whose grammar is
fixed so the block drops verbatim into an issue body's observer-demonstration
section; the no-filing property is a tested forbidden surface rather than a
promise; escalation signals carry a bounded class list and no instructions; and
the catalogue tracks each class's lifecycle so "who legislated this class, and
was its stock swept" is a readback rather than archaeology.

## Boundary

Not a fourth judgment angle. `spatial-loop-grounded` issues clause verdicts,
`context-closure-engineering` compiles bounded projections, `dynamic-workflow`
classifies runtime liveness, and the unadmitted `shadow-architect`
(ed3c/skill-concerns#75) will carry the architecture angle. Those read and
question; this one executes falsification. The differential is the verb.
