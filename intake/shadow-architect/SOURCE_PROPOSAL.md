# Source proposal — shadow-architect

Owner decoupling directive, 2026-09-01, filed as ed3c/skill-concerns#75. Frozen
here by content digest before any refactoring; the bundle is derived from this
brief and from the pinned pstack ceremonies named in
`intake/shadow-architect/source-lock.json`.

## The dependency this retires

The machine layer is already nearly clean of `/Users/neon/skills-shared`: the
noodles code references are retired path strings, the providers lock carries
only an explicitly disabled compat entry, host launchd and backup have zero
references, and this repository's intake source-locks are frozen provenance. The
one live consumer left is the dispatch layer — every wave's Shadow-architect
monitor prompt reads that host directory for architecture principles. Host path,
no pin, no digest, local and remote divergence measured in hundreds of commits:
the exact ambient-dependency class the same day's island audit condemned for
tools on the search path.

## What migrates, and what does not

Extraction, not wholesale import. Only the principles wave monitors have
actually cited migrate, each grounded in a wave receipt naming where it earned
its place:

1. over-design and unrequested abstraction — a field, key or layer no process
   resolves;
2. boring over clever — a mechanism that needs prose to read as correct;
3. the stale-list anti-pattern — a second literal of a set that already exists;
4. author-memory-convention-as-shape-defect — availability is not use;
5. the smallest diff that satisfies the issue, and no gate widened to fit it;
6. restated-copy refusal — point at the owner, never restate it;
7. ambient versus admitted dependency judgment.

The corpus behind those principles does not migrate, and the fate of the source
directory itself — merge, archive, personal use — is the operator's and is out
of scope.

## Shape

Domain-rich and domain-decoupled per the established pattern: a portable
architecture policy carrying the domain-free kernels, a domain ledger carrying
this ecosystem's instantiation, and eval fixtures that are REAL judged diffs
from the wave record rather than invented examples. Each precedent names the
wave receipt that recorded the finding, the monitor record that wrote it down,
the commit whose diff it was issued against, and a control diff where the same
clause must stay silent.

## One organ, two roles

- **SHADOW is the monitor role itself.** Reader-only judging at stage
  boundaries: numbered findings with quoted bytes, receipts plus questions —
  the mode every wave already runs, now reading admitted bytes rather than an
  ambient directory.
- **BUILD is precedent fold-in.** A new judged precedent from a wave receipt
  becomes a clause candidate on a branch behind the landed cure-authorization
  gate; the machine ceremony lands it. No auto-application, and a detection
  never authorizes the clause it detects.

## Boundary

Not a falsification engine. The sibling monitor that owns the falsification verb
executes experiments; this one reads and asks, and the differential is
deliberate. Not a fourth judgment angle either: supervised-conduct verdicts,
bounded context projections, dispatch-runtime liveness and capability-arrival
audit all have owners. This one judges the shape of a change.

## Completion criterion

After landing, the standing dispatch formula's wave-route line replaces the host
path with the pinned skill. That switch is the dispatcher's to execute; until it
happens the decoupling is not complete, and no document in the bundle may claim
otherwise.
